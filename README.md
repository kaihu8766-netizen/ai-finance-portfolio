## 这是什么

面向 **集团总部资金 / 司库、财务分析、财务数字化** 方向的作品集。里面是两件能在线交互的财务系统原型：一件做集团贷款的还本付息排程与利息计提，一件做 LPR 均值回归示意分布与融资成本情景分析。

## 运行与参数口径

- 浏览器模拟器：默认3,000条路径，可调500–10,000条。滑块用于独立假设实验；默认参数与Python一致，随机数实现不要求逐条相同。
- 基准参数（利率以百分点表示）：1Y r0=3.0、θ=2.7、κ=0.10、σ=0.11096868741576088；5Y r0=3.5、θ=3.0、κ=0.25、σ=0.22。σ是演示扩散参数，单位为百分点/√年；不是历史估计波动率。长期中枢差不保证路径不倒挂。
- 安装依赖：`python -m pip install -r demo/requirements.txt`。
- `python demo/lpr_monte_carlo.py`：固定种子42、10,000条Vasicek/OU路径，输出`demo/lpr_mc_paths.png`、`demo/lpr_mc_quantiles.csv`和终端模拟频率；CSV为2026-08至2031-07的1Y/5Y条件分位数。
- `python tools/lpr_mc.py`：独立的贷款利息原型，使用**小数年利率**（如0.03代表3%）、元本金、bp加点，Actual/360左闭右开计息；计息与模拟接口固定每年1月1日重定价；周年日辅助函数不代表排程接口支持该模式。随机游走仅用于给定假设下的利息分布练习，终端输出分段台账及均值/分位数，不生成PNG/CSV，也不参与Pages部署。该模块不建模摊还、季/月付息或节假日扣款，不等同于浏览器司库排程。
- 司库Demo保留原9笔合成合同，默认另含1笔可勾选的3年期情景验证演示贷款，可继续新增；展示日期决定存续余额与状态。结息日计入本期、次日扣款；到期日不计息，只有扣款日遇周末顺延。页面和Excel使用同一份按周年日切段的排程。Chart.js 4.4.1、ExcelJS 4.4.0与许可证本地部署；iOS Safari导出仍待真机验收。


## 两件作品的CSV联动

- 唯一利率桥梁是`demo/lpr_mc_quantiles.csv`，由现有Python脚本生成，模型与参数保持不变。两页通过本地相对路径读取，同源HTTP/离线本地HTTP服务可用；直接打开file页面受浏览器限制时，可手动选择同一份CSV。不引入外部数据请求、缓存副本或写死的次年定价回退。
- 贷款页默认中间情景，可选乐观情景（利率偏低）、中间情景（默认）和悲观情景（利率偏高）；首年合同LPR仍为3.10%，此后每个放款周年日取对应月份的**1Y**条件分位值，锁定至下一周年日，合同加点固定。不插值，超出CSV覆盖月份的重定价拒绝测算。
- 原9笔12个月合同不改期限、金额或首年基准；到期日就是首次周年日，到期前未重定价，所以三档利息相同，LN2026-001末期25天仍为157,986.11元。三档相同是合同结构的正确结果。
- 另加可勾选的`SCENARIO-DEMO-001`：100万元、2026-08-01至2029-08-01、加点20bp，明确标注“为验证利率情景而新增的演示贷款”。默认包含此笔，原9笔与新增演示贷款分组列示；取消勾选可单独查看/导出原9笔。
- 汇总按展示日（含）至到期日（不含）的尚未发生利息计算，沿用Actual/360、周年日切段、结息与舍入规则。旧版首年3.10%/后续3.00%仅作为复算对照；页面列出中间情景差额。未来利息成本与按扣款日汇总的未来应付现金流分开，不混用LPR页1亿元5年期人为示例金额。
- 乐观、中间、悲观三档利率情景为月度边际利率分位序列构成的确定性情景，不是随机路径，也不是贷款利息的分位数、置信区间或政策发生概率；结果是该情景下的条件测算，不是预测。60%/25%/15%仍为另行设定、未经统计校准的主观权重，不用于三档加权。
- Excel随选择重算，带上情景标记、逐笔CSV引用、60个月原始分位值、分组未来成本与旧口径对照。导出是该选择的快照；切换情景后重新导出。

回归检查（无npm依赖）：`node --test tools/test_lpr_scenarios.js`，覆盖单位换算、月份/分位数校验、覆盖期边界及同源读取限制。

## 质量控制是怎么做的

财务数据对准确性零容忍，而 AI 生成的代码与测算容易"看起来对"。所以我把金融机构的 **经办 — 复核 — 审批（Maker-Checker）** 机制搬到数据建模里：

1. **经办**：按 Actual/360、季末月 20 日结息、年度重定价等规则，由 AI 生成计算代码；
2. **复核**：换另一个模型独立验算现金流与折现结果，交叉比对边界异常；
3. **裁决**：本人核验勾稽关系与数据口径后放行。

这套逻辑与「前后台制衡、四眼原则（Four-Eyes）」一致：经办与复核分离，分歧沉淀为规则，对外交付的测算报表要求逻辑闭环、可追溯。

借鉴职责分离与独立复核原则，不等同于银行模型风险管理中的独立模型验证，也不代表监管意义上的审批。
