# 跨项目机制契约 v1.0（抽象层 · 两边同内容）

> 由 F-20260923-02 跨项目机制回灌评审（PF-RV-20260923-10/11）确立。
> 本文件为**抽象层**契约：机制名、版本号、边界约定、编号域规则，两边逐字一致。
> **实现层**（具体路径/脚本名/业务细节）仅留在各仓私有文档，不写入本契约。

## 1. 参与者
- 协作A：另一协作项目（独立双仓，内部细节不在本契约披露）
- 协作B：ai-finance-portfolio（公开单仓，仓内 trace/ 目录排除出 Pages 构建）

## 2. 编号域规则（全局唯一）
- 裸 `RV-YYYYMMDD-NN`：**仅协作A专用**（历史约束，PF-RV-20260923-10 确认边界仍成立）
- `PF-RV-YYYYMMDD-NN`：作品集专用（域前缀即全局唯一）
- 未来第三方使用裸 RV- 时：必须先声明域前缀或改用带域前缀编号（C5 入口规则）
- 同日内两个仓各自递增，域前缀保证不撞号

## 3. 机制核心（两边一致）
- **事前对齐**：功能提交（feat/fix/refactor/perf）必须引用已批准（adopted）且 phase=scheme 的方案评审
- **权威源**：评审档案（RV 档案）= 唯一权威；project-state 仅缓存视图
- **先归档后提交**：评审档案先入库，再提交代码

## 4. 红线类别（两边各自映射到本仓路径）
- gate_self：门禁自身（改门禁=绕过全部闸门，必审）
- 发布产物：对外部署的文件（index.html / demo / assets 等）
- 数据红线：真实数据（发票）或公开渠道（作品集）的敏感内容

## 5. 已知边界与残余风险（两边共同承认）
- commit 时间可伪造（权威时间锚定 RV 归档提交）
- 本地 hook 可被 --no-verify 绕过（CI 为不可绕过兜底）
- 新克隆需 git config core.hooksPath .githooks 才生效

## 6. 一致性维护
- 本契约版本号 v1.0；任一侧修改契约必须：走本侧评审机制留档 + 更新版本号 + 同步另一侧
- 两侧各存一份；以先落档侧的档案为权威源，另一侧为镜像
- 一致性校验：版本号 + 内容 hash。hash 值不写入本文件（避免自引用），固化于 DEC-20260924-03；校验命令 sha256sum CROSS_PROJECT_CONTRACT.md
