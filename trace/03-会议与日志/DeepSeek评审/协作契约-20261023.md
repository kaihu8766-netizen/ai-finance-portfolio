# 双 Agent 协作契约 v1.2（2026-10-24 用户拍板：v1.1 + 第 10/11 条 Gemini 外部评审通道）

## 第 1 条 分工
执行 Agent（DSH 内 DeepSeek，带工具：写代码、跑 preflight/pytest/coverage、浏览器实测、commit/push）；独立复核 Agent（豆包，带工具：独立 pull、复测复算、axe、RV 档案、REVIEW_STAMP 盖章、发布、线上验证）；复核 AI（DS API，异模型，评审输入）；外部评审 AI（Gemini，多模态，评审输入，见第 10/11 条）；人（胡凯）拍板/裁决终审。

## 第 2 条 A/B 分类
A 类：用户可见口径/数字/叙事/结构/契约与门禁改动 → 对齐单 → 补挑刺 → 人拍板 → 落档 → 执行 → 三件套 → 独立复核复测 + 复核 AI 评审（+ 涉及视觉/长文/英文默认调外部评审 AI）→ 盖章 → 发布 → 线上验证。
B 类：bugfix/样式/文案小改 → 不调复核 AI、不调外部评审 AI（除非用户点名）；三件套 + 独立复核复测 + 档案「自审」记录。

## 第 3 条 唯一真源与提交纪律
唯一真源 = 远程 master；DSH pull --rebase 后 push 内容 commit 并登记 sha；盖章只由豆包写 REVIEW_STAMP 批准行（单 sha）；docs/档案 commit 走豁免（不触发 Review gate 内容比对）。

## 第 4 条 复核门禁
check_review_stamp.py：从 HEAD:REVIEW_STAMP.md 正则取最新已批准行 sha，git diff 比对内容（EXCL 排除档案类文件）；未盖章内容 commit 的 Review gate 必红、Deploy 前拦截；门禁纯机械，从不调任何 AI。

## 第 5 条 红线与数据安全
禁改文件（门禁脚本/REVIEW_STAMP/契约本身改前必审）；真实发票/密钥/凭证/真实人名/雇主品牌/PII 绝不进公开仓（尤其 public）；合成演示数据可含泛化银行名。

## 第 6 条 线上验证
每个里程碑版本：部署后核线上特征 + 旧值残留扫描；iOS Safari 真机未验时如实标注。

## 第 7 条 讨论触发
机器判据 high（红线/不可逆/对外交付）、结论不一致（含复核 AI 与外部评审 AI 冲突）、执行方自报不确定、人明确要求——满足任一发起讨论；同一主题连续 3 轮无新论点转人裁决；结论三态：通过/有条件通过/拒绝。

## 第 8 条 版本与统计口径
时间线只记作品里程碑；页面「轮复核/条批准基线」必须与 REVIEW_STAMP 实际行数同步（每轮盖章后回填；历史条目保留真实值）。

## 第 9 条 DS API 定位（v1.1 追加）
A 类内容 commit 必跑 DS API 复核（异模型+哈希留痕）；B 类不调；CI Review gate 纯机械（不调 API、不产出结论）；红线/禁改文件由 preflight + check_review_stamp 机械保；DS API 结论是输入非判决，裁决权归独立复核 Agent + 用户（RV-81 KPI 舍入误判为实例）。

## 第 10 条 外部评审 AI（Gemini）定位（v1.2 新增）
外部评审 AI（Gemini）= 外部评审通道：多模态视觉审查（截图/布局/响应式）、长文逻辑交叉、英文润色；无仓库写权限/无工具执行/无盖章/无发布权；结论是输入非判决，裁决归独立复核 Agent + 用户，不替代豆包终审（不与第 4/9 条冲突）；不参与门禁（CI Review gate、preflight、check_review_stamp 均不依赖 Gemini，Gemini 结论不得作为门禁判据）。

## 第 11 条 外部评审 AI 调用与留痕（v1.2 新增）
触发：A 类涉用户可见视觉/长文/英文时默认调 + 用户点名随时调；B 类不调（用户点名除外）。
输入：脱敏截图/文案或 diff；禁传真实发票/密钥/凭证/雇主品牌/真实人名/PII，含截图 EXIF 元数据（沿用 v7.7 脱敏基线）。
输出：P0–P2 分级 + 每条证据（截图区域/复算/原文）+ 修复建议，英文句级。
留痕：原文存 out/review/gemini/，摘要进 RV 档案，trace 归豆包域。
分工：Gemini 视觉/英文；DS API diff/逻辑；豆包终审盖章；同一结论不评三次；Gemini 与 DS API 结论冲突 → 触发第 7 条讨论转人裁决。
失败语义：单次调用重试上限 1 次，仍失败跳过并记录原因，不阻塞闭环。

## 统计口径（2026-10-24 核对）
REVIEW_STAMP 实际批准行 = 60（第七十九轮）；页面回填 = 79 轮复核 / 60 条批准基线（v7.12 P0）。
