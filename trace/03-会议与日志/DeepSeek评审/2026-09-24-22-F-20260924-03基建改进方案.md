## DeepSeek 结论（原文节选）

**方案 A + B 方向可行，建议"修订后放行"（adopted with revisions）。** 方案 A 仅剩 ROOT 注入口径需定死；方案 B 存在一处技术硬伤（"commit 的 pushed_at"不存在），必须修正后才能批准。以下按红线类别 gate_self 走 PF-RV 归档流程。
可行，测试设计（tmp_path 隔离仓、假 commit 模拟）符合"不修改真实仓状态"的要求。但三个边界必须在本方案内收口，否则 diff_hash 不确定：
1. **ROOT 注入方式必须二选一写死**（Blocker）。方案里"需确认"这一项不能留给实现阶段——它直接决定 `trace_gate.py` 的 diff。建议：显式参数优先 + `TEST_ROOT` env 兜底，且 fixture 内断言 `ROOT != 真实仓根`，杜绝测试误写真实仓。
2. **cmd_check 的"PF-RV 伪造号→exit=1"需定义清楚。** 应明确为"档案权威源中不存在该 PF-RV-ID 或其 phase/状态不满足"，与 project-state.md 缓存视图的校验口径对齐，避免测试固化一个将来会变的虚构规则。
3. **测试文件自身的保护级别。** `tests/test_trace_gate.py` 若可被随意删除/改断言，等于绕过 gate。建议把该测试文件一并纳入 gate_self 清单（至少要求改动必须带 PF-RV-ID），否则回归套件是"软保护"。
补充顺序问题：CI 中 pytest 应作为前置步骤，失败即阻断后续 gate 步骤，语义与现有 review-gate 一致。
- **GitHub 没有 commit 级的 `pushed_at`。** `pushed_at` 是仓库级字段；commit API 返回的 `author.date`/`committer.date` 就是 Git 对象里的元数据，**本地 GIT_COMMITTER_DATE 能直接伪造，GitHub 不改写**。用它做锚点等于没缓解 ISS-20260923-01。
- commit 级真正不可伪造的平台时间是：`PushEvent.created_at`（events API）、或 PR 的 `merged_at`、或 Actions run 的 `created_at`。其中 events API **只保留约 90 天**且可能聚合多 commit，**不能作为长期审计源**。

## 修订决策落档（DeepSeek adopted-with-revisions，2026-09-24）

### A-1 ROOT 注入方式（定死）
- trace_gate.py 顶部：`ROOT = Path(os.environ.get("TRACE_GATE_ROOT", "")) or Path(git rev-parse --show-toplevel)`
- 测试 fixture：`monkeypatch.setenv("TRACE_GATE_ROOT", tmp)` + 断言 `ROOT != 真实仓根`（在测试内 import 后立即断言），杜绝误写真实仓

### A-2 PF-RV 合法性判定口径
- 判据 = 档案权威源（trace/03-会议与日志/DeepSeek评审/ 下存在该 PF-RV 档案且 phase=scheme 且 status=adopted）
- 与 project-state.md 缓存视图无关（缓存仅展示，不做校验依据）

### A-3 测试文件纳入 gate_self
- gate_rules.yaml gate_self.paths 追加 `"tests/"`（tests/ 下改动须带已批准 PF-RV-ID）
- review-gate.yml 增加 pytest 前置步骤：pytest 失败即阻断后续 gate（fail fast）

### B-1 锚点来源（修正硬伤）
- GitHub **无 commit 级 pushed_at**（pushed_at 是仓库级字段；commit API 的 author/committer.date 即 Git 元数据，本地可伪造）
- 锚点改用：① PR `merged_at`（合并入 main 的平台时间，长期可查）② PushEvent `created_at`（events API，仅存 90 天，作短期校验）③ Actions run `created_at`
- 落盘快照：audit_time_anchor.py 查询到平台时间后写入 `trace/platform-time-anchors.jsonl`（append-only），保证 90 天后审计可复现

### B-2 方案后补阈值 T
- 判定：评审归档平台时间 > 首次引用 F-ID 的 push 平台时间 + T，T=1 天（同日不算后补，粒度避免时钟差误判）
- 规则写入 audit-scheme 增强逻辑 + 本档案

### B-3 本地/CI 语义区分
- 本地无 GITHUB_TOKEN 或网络不可达 → 输出 `SKIP (unverified)` 且 exit 0（提示性，不阻断）
- CI（review-gate.yml 内）有 GITHUB_TOKEN → 执行真实校验，失败 exit 1 阻断合并
- 不得把 SKIP 当 PASS 展示
